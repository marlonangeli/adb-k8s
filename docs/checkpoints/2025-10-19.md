# Checkpoint – 2025-10-19

## Resumo do estado atual

- Cluster bare-metal com Cilium (v1.18.2), Hubble, observabilidade via kube-prometheus-stack e armazenamento Longhorn operacional.
- Ingress NGINX distribuindo tráfego do pool do MetalLB, certificados desabilitados por padrão (acesso HTTP interno).
- Rancher removido e namespace `cattle-system` limpo após conflitos de versão.
- vClusters provisionados por tenant (perfil privado) e um vCluster compartilhado; kubeconfigs publicados em `monitoring`.
- Argo CD instalado no namespace `argocd`, exposto via HTTP e integrado com os repositórios Git das aplicações.

## Automação disponível

- `bin/95-argocd.sh`: instala/atualiza o Argo CD, registra todos os vClusters e cria as Applications GitOps (com verificação de clusters já configurados).
- Toolkit em `scripts/vcluster/` provê criação, atualização e remoção de vClusters (incluindo limpeza de secrets e state) e gera automaticamente hosts `api-<tenant>.<ip>.sslip.io` / `interpolation.<ip>.sslip.io` nos overlays Kustomize.
- Makefile atualizado: `make argocd` executa o estágio final após `make vcluster`.

## Componentes GitOps

- `adb-api-3`: manifests refatorados para Kustomize com overlays por tenant (`k8s/tenants/<tenant>`), banco Postgres com Longhorn, policies de rede e HPA.
- `adb-interpolation-api`: base compartilhada com Service `LoadBalancer`, Ingress `least_conn`, HPA e políticas alinhadas ao acesso multi-tenant (hosts sincronizados com o IP do vCluster `shared`).

## Observabilidade e testes

- Secrets `vcluster-*-kubeconfig` disponíveis em `monitoring` permitem importar os vClusters no Grafana/Hubble.
- Recomenda-se executar smoke tests: `kubectl get nodes`, `cilium status`, `kubectl -n monitoring get pods`, `argocd app list`.
- Ambiente de testes de carga previsto para máquina externa com k6; ver `tests/k6/README.md` e `docs/testing-guidelines.md`.
